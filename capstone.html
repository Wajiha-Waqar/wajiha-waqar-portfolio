Leakage-Aware Content Refresh Opportunity Scoring

FlyRank ML Internship • Capstone • Machine Learning Track

Problem

Content teams often have more pages worth investigating than they can review at once, which creates a prioritization problem: which pages should a human content or SEO reviewer inspect first?

The research question was whether March-only, non-label-derived search and engagement signals can rank content that subsequently meets a predefined refresh-review condition in April. The intended output was a ranking and triage system to support human review — not an automated publishing or content-management system, and not a claim about Google's ranking algorithm or the causal effect of refreshing content.

My Role

  • Defined an operational research outcome (refresh_outcome) using minimum impressions, measurable CTR, and a subsequent CTR decline threshold
  • Built month-to-month development panels (January→February, February→March) and held out a future test window (March→April) so evaluation never saw information from the future
  • Engineered a 26-feature set from search position, GA4 engagement, and traffic-channel signals, explicitly excluding outcome-derived fields
  • Ran a final leakage audit to confirm no future or outcome-derived fields entered the predictive feature set
  • Compared Logistic Regression and Random Forest using a client-grouped internal validation split, selecting the model on Average Precision before touching the future test set
  • Evaluated the selected model against a fixed Week-4 baseline on the same held-out future test window
  • Converted model scores into a tiered human-review queue with reason codes and an explicit list of actions that should not be automated
  • Documented limitations, including the observational nature of the data and the absence of any causal refresh claim

Lessons Learned

  • Outperforming a fixed baseline on a genuine future window still only supports decision-making — it doesn't prove causation.
  • A leakage audit has to check for outcome-derived fields even after the obvious ones (impressions, CTR) are already removed.
  • Client-grouped validation keeps a model from learning client identity instead of a general, transferable signal.
  • Reporting relative concentration (e.g. Precision@20 vs. the base rate) communicates value more honestly than a single accuracy number on its own.
  • Listing what should not be automated is as important as what the model recommends.
